Functional and technical documentation for the suite, plus the status and conventions of its Model Context Protocol servers. The marketing site explains what the apps are for; this one explains how they work, how to run them and where an agent has a real interface.

Two documentation sites, on purpose. The marketing site (chuucommie.github.io/igeltools-web) is for introducing the apps. This site holds the details: behaviour, protocols, storage, security, limitations and MCP tools. If a claim belongs in an implementation, it belongs here.

The suite

Living-room control

Igel TVRemote

A network remote for smart TVs: discovery, pairing, keys, text and wake-on-LAN. Apple platforms; the core is a Swift package with one adapter per TV protocol.

Writing and thinking

IgelNotes

A 21-type block editor on SwiftUI and SwiftData, with Pencil drawing, Siri intents, an assistant and optional Appwrite sync. CloudKit is planned, not active.

Server control

IgelServer

Native macOS and iOS clients for a headless Linux server over SSH: telemetry, systemd, Docker, qBittorrent, SMB shares and an encrypted vault.

Suite management

IgelLauncher

Installs, updates and opens the other three. Native Rust and egui, OS/CPU asset selection, SHA-256 verification and a stdio MCP server.

Release state differs by app. IgelServer's source version is 2.2.0 and its pipeline is set up to publish a DMG update feed; the macOS, iOS and watchOS TVRemote targets and IgelNotes have no published release yet. The source repositories are private.

For agents

An MCP server is the suite's goal, not a shipped property of every app. IgelLauncher is the only current implementation. IgelServer lost its Rust igelserver-mcp helper when the Tauri client was removed, and Igel TVRemote and IgelNotes expose App Intents but no MCP server. The MCP overview records that status, the conventions a future server must follow, and how to register the launcher.

# IgelLauncher — catalog, installs, updates, settings
igellauncher mcp

The existing server speaks JSON-RPC over stdio, writes logs to stderr, and never exposes secrets in tool results. Tools that change the machine are annotated as non-read-only so an MCP host can ask for approval.
