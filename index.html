Functional and technical documentation for the suite, plus the contract for every Model Context Protocol server. The marketing site explains what the apps are for; this one explains how they work, how to run them and how an agent can drive them.

Two documentation sites, on purpose. The marketing site (chuucommie.github.io/igeltools-web) is for introducing the apps. This site holds the details: behaviour, protocols, storage, security, limitations and MCP tools. If a claim belongs in an implementation, it belongs here.

The suite

Living-room control

Igel TVRemote

A network remote for smart TVs: discovery, pairing, keys, text and wake-on-LAN. Apple platforms; the core is a Swift package with one adapter per TV protocol.

Writing and thinking

IgelNotes

A block editor on SwiftUI, SwiftData and CloudKit, with Pencil drawing, Siri intents and an assistant that can work on notes.

Server control

IgelServer

A remote console for a headless Linux server over SSH: telemetry, systemd, Docker and qBittorrent, on macOS and on the Steam Deck.

For agents

Every app in the suite is required to ship a Model Context Protocol server. Two are implemented today; the Apple apps have a stable contract and their macOS servers are the next milestone. The MCP overview covers transports, client registration, error conventions and security.

# IgelLauncher — catalog, installs, updates, settings
igellauncher mcp

# IgelServer — SSH telemetry, systemd, Docker, qBittorrent
igelserver-mcp

The servers speak JSON-RPC over stdio, write logs to stderr, and never expose secrets in tool results. Tools that change the machine are annotated as non-read-only so an MCP host can ask for approval.
