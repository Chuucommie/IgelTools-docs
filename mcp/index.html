Docs / MCP

Four servers, one local model.

Every IgelTools app now exposes an MCP surface. Three are stdio binaries; IgelNotes runs a loopback HTTP server inside the Mac app (the runtime can bind on iPadOS, but the iPad UI does not expose it yet). IgelServer adds a foreground-only HTTP server on iOS, reachable over the local network with a bearer token. The stdio servers and the Mac loopback servers are not reachable from the network.

Protocol 2025-06-18 JSON-RPC 2.0 stdio · loopback HTTP 94 tools across surfaces

IgelServer's macOS helper and Igel TVRemote's helper live inside their macOS app bundles. IgelServer also runs a foreground-only HTTP server inside the iOS app. IgelNotes is not a separate binary: the server starts from Settings → Server MCP on Mac and is off by default. The iPad runtime exists but the current iPad UI has no toggle; iPhone never hosts a server.

Register a server

stdio: launcher, server, TV remote

{
  "mcpServers": {
    "igellauncher": {
      "command": "/Users/you/Applications/IgelLauncher.app/Contents/MacOS/IgelLauncher",
      "args": ["mcp"]
    },
    "igelserver": {
      "command": "/Applications/IgelServer.app/Contents/Helpers/igelserver-mcp",
      "env": { "IGELSERVER_PROFILE": "home", "IGELSERVER_SCOPE": "read" }
    },
    "igeltvremote": {
      "command": "/Applications/Igel TVRemote.app/Contents/Helpers/igeltvremote-mcp"
    }
  }
}

HTTP: IgelNotes (and optional IgelServer HTTP)

{
  "mcpServers": {
    "igelnotes": {
      "type": "http",
      "url": "http://127.0.0.1:8765/mcp",
      "headers": { "Authorization": "Bearer <token from Settings → Server MCP>" }
    },
    "igelserver": {
      "type": "http",
      "url": "http://127.0.0.1:8787/mcp",
      "headers": { "Authorization": "Bearer <IGELSERVER_HTTP_TOKEN>" }
    }
  }
}

IgelServer HTTP mode is started explicitly with igelserver-mcp --http. Its server card is at GET /mcp/server-card. IgelNotes starts its listener when the toggle is enabled; the endpoint path is fixed at /mcp.

IgelServer on iOS uses Settings → Server MCP iOS, advertises _igelserver-mcp._tcp over Bonjour, and serves http://<device>.local:8788/mcp with the token shown in the app. It stops when the app leaves the foreground.

claude mcp add igellauncher -- /Users/you/Applications/IgelLauncher.app/Contents/MacOS/IgelLauncher mcp

Conventions

RuleValue
Wire protocolJSON-RPC 2.0; newline-delimited on stdio, JSON body over HTTP.
MCP version2025-06-18. IgelNotes accepts older client versions; IgelServer HTTP validates newer protocol headers.
BindingsNo listener for stdio. IgelNotes binds 127.0.0.1:8765; IgelServer's macOS HTTP helper binds 127.0.0.1:8787; the iOS server listens on the local network through Bonjour on port 8788 while the app is in the foreground.
AuthBearer token for HTTP. IgelNotes stores it in the Keychain; the IgelServer macOS helper reads or generates IGELSERVER_HTTP_TOKEN; the iOS server generates a token shown in Settings.
Tool resultsText block with JSON. Tool failures use isError: true; protocol failures use JSON-RPC errors.
ScopesIgelServer's macOS helper and IgelNotes filter tools by read/write/destructive profile. The iOS server exposes a fixed 10-tool set. The launcher and TV remote gate per-tool hints and flags.
Resources / promptsIgelNotes and IgelServer's macOS helper expose both. IgelServer iOS is tools-only. Igel TVRemote exposes tools and read-only resources. IgelLauncher is tools-only.
AnnotationsreadOnlyHint, destructiveHint, idempotentHint; network tools may set openWorldHint.
SecretsNever returned. Tokens and passwords are reported as boolean *_set fields.
Loggingstderr and/or the app log file. stdout is always the protocol channel.

Security guidance

  • An MCP server is as powerful as the app it belongs to. Only register servers in agents you trust and gate write tools with the host's approval mechanism.
  • Prefer read-only modes for exploration: IGELSERVER_SCOPE=read, the IgelNotes Sola lettura profile, --read-only for TVRemote.
  • IgelNotes and the IgelServer macOS HTTP server bind loopback only. The IgelServer iOS server is foreground-only and uses a bearer token on the local network; keep it on trusted Wi-Fi and do not expose it through a proxy.
  • IgelNotes stores its token in the Keychain; the IgelServer macOS helper uses the environment; the iOS server shows its token in Settings and regenerates it on launch. Do not paste tokens into prompts or logs.
  • IgelServer destructive tools require IGELSERVER_SCOPE=destructive plus an elicitation confirmation; they are never available in read scope.
  • The launcher stores an optional GitHub token in plain text in settings.json; the server reports only whether it is set.
  • Review the install path before a launcher install: the checksum is enforced, but the target directory comes from Settings.
  • Run each server as your user; none needs root.

Troubleshooting

SymptomCause and fix
No release published yet (launcher)The repository has no release or the tag prefix does not match. Check the shared release repository and the app's release_prefix.
rate-limit (launcher)GitHub's unauthenticated limit was reached. Add a token in Settings.
checksum mismatchThe asset and checksum disagree. The download is deleted and the install stops.
scope_denied (server)The requested tool is above IGELSERVER_SCOPE. Raise the scope deliberately or use a read-only tool.
SSH failure (server)The helper uses /usr/bin/ssh, the profile key and BatchMode=yes. Check the profile, key and known hosts; read the audit log for the failing tool.
not paired (TVRemote)Pair the TV in the app first. The MCP server cannot pair, launch apps or run discovery.
unsupported (TVRemote)The protocol lacks that capability; the error carries a hint. Use server.info or tvs.get first.
IgelNotes returns 401Token missing or regenerated. Copy the current token from Settings → Server MCP.
IgelNotes is not reachableThe server is off by default, is exposed in the Mac settings, and has no iPad toggle yet. Enable it on the Mac and check the port.
IgelServer iOS is not reachableThe iOS server runs only while the app is in the foreground and needs Local Network permission. Check Settings → Server MCP iOS, the Bonjour name and the bearer token.

Roadmap

  • Keep the four servers in sync as the apps evolve; add integration tests for each transport.
  • More resources and prompts where they help agents avoid guessing: release notes, diagnostics and common workflows.
  • In-place launcher self-update, exposed through the same MCP surface once the window can do it.
  • Optional remote transport hardening for IgelServer HTTP; loopback remains the default.
