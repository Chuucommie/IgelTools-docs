One app, one server, for now.

IgelTools treats an agent as another user of the same app, but only where a real server exists. IgelLauncher ships one over stdio. IgelServer, Igel TVRemote and IgelNotes do not; their current agent surface is App Intents or nothing.

Protocol 2025-06-18 JSON-RPC 2.0 Newline-delimited stdio

The Apple apps do not have servers today. IgelServer's Rust helper was removed with its Tauri client, and Igel TVRemote and IgelNotes expose App Intents but no MCP binary. A future server would need a macOS process that opens the app's own store and Keychain, so these remain design targets rather than contracts with a binary behind them.

Register a server

Claude Desktop / Claude Code style configuration

Most clients accept an mcpServers object. Use the absolute path to the binary and the arguments it needs:

{
  "mcpServers": {
    "igellauncher": {
      "command": "/home/you/.local/bin/igellauncher",
      "args": ["mcp"]
    }
  }
}

Claude Code

claude mcp add igellauncher -- /home/you/.local/bin/igellauncher mcp

Any stdio client

Start the binary as a child process and exchange one JSON object per line on stdin/stdout. The first exchange is:

{"jsonrpc":"2.0","id":1,"method":"initialize","params":{
  "protocolVersion": "2025-06-18",
  "capabilities": {},
  "clientInfo": {"name": "my-agent", "version": "0.1.0"}
}}
{"jsonrpc":"2.0","method":"notifications/initialized"}
{"jsonrpc":"2.0","id":2,"method":"tools/list"}

Conventions

The launcher implements the following conventions. They are the rules a future server for any of the Apple apps would have to follow.

  • Tools only. The server exposes tools; resources/list and prompts/list return empty arrays.
  • Text results. A successful call returns one text content block with pretty-printed JSON. A failed tool returns isError: true and a readable message.
  • Annotations. Read-only tools set readOnlyHint; tools that use the network set openWorldHint. A host can use them to require approval.
  • No secrets. The launcher reports github_token_set. A future server that reads profiles would report password_set and similar booleans. Tokens and passwords are never returned.
  • Logging. stderr and the app log only. stdout is the protocol channel.
  • Local process. No TCP listener. To reach another machine, run the MCP server on the machine that owns the app.

Security guidance

  • An MCP server is as powerful as the app it belongs to. Only register servers in agents you trust, and gate write tools with the host's approval mechanism.
  • Prefer read-only tools for exploration; ask the agent to call list_* before actions.
  • Keep the launcher's GitHub token in the MCP client's environment, not in prompts or logs.
  • Review the install path before granting a launcher install: the checksum is enforced, but the target directory comes from Settings.
  • Run the server as the same user as the app; do not run it as root.

Troubleshooting

SymptomCause and fix
No release publishedThe repository is private or has no releases. Add a GitHub token in the launcher, or publish a tagged release.
rate-limitGitHub's unauthenticated limit was reached. Add a token; the launcher maps this to a readable error.
checksum mismatchThe asset and the published checksum disagree. The download is deleted; do not install it manually.

Roadmap

  • Servers for IgelServer, Igel TVRemote and IgelNotes, built as macOS processes that reuse each app's store and Keychain.
  • Optional Streamable HTTP transport for agents that cannot start a process.
  • MCP resources for release notes and app documentation, and prompts for common workflows.
  • In-place launcher self-update, which the MCP surface will expose once the window can do it.
