IgelNotes

A block editor in the Notion mould for the Apple stack: pages made of blocks, CloudKit sync, Pencil drawing, Siri intents and an assistant that can work on the page with you.

iPhone · iPad · Mac SwiftUI · SwiftData · CloudKit MCP contract v1 No release yet

Overview

IgelNotes stores a note as an ordered list of typed blocks. Notes belong to workspaces, sync through the user's own iCloud container, and can be shared with other people through CloudKit sharing. The same page is the unit the assistant, the Siri intents and the future MCP server operate on.

Functional documentation

What you can do

  • Write in blocks: headings, text, todos, lists, quotes, code, tables, dividers and drawings.
  • Organise notes in workspaces, tag them, mark favourites, and recover deleted notes from the trash.
  • Use a Notion-style page: emoji, cover, nested notes and a short block toolbar.
  • Sketch with Apple Pencil on iPad; drawings are blocks in the page, with Scribble handwriting support.
  • Ask Siri or Shortcuts to create a note, append text, search or open one; a shopping-list intent builds todo blocks.
  • Work with the assistant using OpenAI, Anthropic, Ollama or Apple Intelligence, with keys kept in the Keychain.
  • Export a note or send it to an external agent (Hermes) where configured.

  • No Windows, Android or Linux build is planned for the current architecture.

Sync and storage

  • CloudKit: SwiftData models map to a private CloudKit database in the user's container; no IgelTools server is involved.
  • Sharing: notes keep a CKRecord identifier for ShareKit collaboration and a private/shared status.
  • Secrets: AI provider keys and service tokens live in the Keychain through KeychainHelper.
  • Optional services: an Appwrite client and an external agent (Hermes) integration exist for specific workflows; both are configured by the user and are not required.

Assistant providers

OpenAI, Anthropic, Ollama and Apple Intelligence are selectable. Providers that need a key or base URL read them from the provider configuration; keys are stored in the Keychain. The assistant can propose block changes, which the user applies in the editor.

MCP contract

Contract v1 macOS server next Binary: igelnotes-mcp

Status. The tools below are the frozen v1 contract. The server will be a macOS executable that opens the same SwiftData store and reuses the App Intents, so an agent can read and write notes without a second database. It is the next milestone after the TVRemote server.

Design

  • Runs on the Mac that owns the notes; it does not talk to CloudKit directly or bypass the app's store.
  • Read tools return note metadata and block content; write tools create or append blocks and mark them as createdVia: "mcp".
  • No assistant key is exposed. Tools that need the assistant reuse the app's configured provider.
  • stdio only; no listener.

Security rules

  • Local stdio; the server runs as the user who owns the store.
  • Write tools are annotated as non-read-only; deletes are not part of v1.
  • Provider keys and CloudKit account details are never returned.
  • Exports return content only; they do not write files outside the app's data folder unless the tool says so.
