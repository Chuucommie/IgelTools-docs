IgelNotes

A block editor for the Apple stack: 21 block types, PencilKit drawing, SwiftData storage, optional Appwrite sync, Siri intents and an assistant that can read and write notes.

iPhone · iPad · Mac SwiftUI · SwiftData · Appwrite CloudKit not active No MCP server No release yet

Overview

A note is an ordered list of typed blocks stored in SwiftData on the device. The app runs fully local. Synchronisation is optional and goes to an Appwrite instance the user configures; CloudKit is not enabled in the current source, despite the model comments and sharing views that mention it.

The same note is the unit used by the editor, the Siri intents and the assistant. An external agent reaches the app through a configured AI provider or through App Intents. There is no IgelTools account and no dedicated HTTP endpoint for an agent.

Functional documentation

What you can do

  • Write in blocks. Headings, text, todos, bullet and numbered lists, toggles, quotes, code, dividers, tables, drawings, images, sub-pages, page links, callouts, video, audio, files and web bookmarks: 21 types in total.
  • Tables. Columns, rows, header row, inline cell editing, add/remove column and row. Table data is JSON stored on the block.
  • Draw. A PencilKit canvas as a block, with Apple Pencil and Scribble on iPad. The drawing is stored as PKDrawing data.
  • Organise. Workspaces, tags, favourites, a Notion-style emoji and cover, nested notes, links between pages, multi-select move and duplicate.
  • Find. Search over titles and block content, plus filters for favourites and tags. The sidebar splits shared and private notes.
  • Recover. A trash with restore and permanent delete; notes older than 30 days are purged automatically.
  • Start from a template. Blank, shopping list, meeting notes, quick note and journal.
  • Dictate. On-device speech recognition through SFSpeechRecognizer (Italian locale), with audio playback.
  • Use Siri and Shortcuts. Create, append, search and open notes; build a shopping list from dictated items.
  • Work with an assistant. OpenAI, Anthropic, Ollama or Apple Intelligence, with keys in the Keychain. Kigel AI can chat, generate blocks and manage notes. The Apple Intelligence service is still a rule-based mock, so use a remote or local model for real output.
  • Sync optionally. Pull and push blocks to Appwrite, with a realtime WebSocket subscription when the endpoint is a hostname.
  • Import. Notes from JSON, Markdown or plain text files. Kigel skills import and export as Markdown with YAML frontmatter.

Limitations

  • The repository contains Swift sources but no Xcode project. You create the project and add the Appwrite Swift package yourself.
  • CloudKit is not active: the iCloud entitlements are commented out and the store is local. The sharing sheet and the CloudKit share code are present but cannot work without that capability.
  • The Apple, Google, Microsoft, Passkey and SSO buttons on the sign-in screen are placeholders, except Apple sign-in, which is a local mock. The working paths are email/password against Appwrite, or Continue without an account.
  • No Windows, Android or Linux target is planned for this architecture.
  • The built-in Apple Intelligence provider is a stub: it waits, returns a canned block list and echoes the prompt. It needs no key and opens no connection, but it does not run a real model. OpenAI, Anthropic and Ollama are real HTTP clients.
  • Appwrite realtime requires a hostname. Direct IP endpoints are refused for the WebSocket subscription, so sync can be configured but realtime will not start.
  • There is no MCP server. The App Intents are the only agent-facing surface.
  • Nothing has been released; the documentation follows the current source, not a shipped build.

Sync and auth

Local store

IgelNotesApp builds a ModelContainer with the schema Workspace, Agent, Note, NoteBlock, AIChat, AIChatMessage and KigelSkill, using a configuration named IgelNotes. There is no CloudKit container and no network dependency for editing.

Appwrite (optional)

DataWhere
isEnabled, endpoint, projectId, databaseId, collectionIdUserDefaults, key appwriteConfig
API keyKeychain, service <bundle id>.appwrite, account apiKey
  • Configuration is empty by default. Nothing is enabled until the user fills endpoint, project, database and collection and turns the toggle on.
  • The service lists documents in the configured collection and maps them to blocks by noteId and block UUID. Uploads use the block UUID as the document id: update first, create if missing. Deletes remove the document.
  • Notes created from remote blocks get createdVia appwrite (or telegram for ids with that prefix).
  • RealtimeViewModel opens an Appwrite Realtime WebSocket and applies incoming create/update/delete events to the local store. It refuses IP hosts because the WebSocket subscription needs a domain name.
  • The SDK is version-sensitive: a client subclass maps Appwrite 1.9's $tableId back to $collectionId so document decoding does not crash.
  • When Appwrite is configured, the editor uses IgelEditorView, which writes through the realtime view model; otherwise it uses the local EditorView.

Authentication

  • With a valid Appwrite configuration, email/password registration and login use the Appwrite Account API and keep a session.
  • Without it, Continue without an account unlocks a local workspace. The session flag and display name live in UserDefaults.
  • Face ID can lock an existing session through LocalAuthentication; the toggle appears only when biometrics are available.
  • Social login buttons are UI placeholders; Apple sign-in currently sets a local mock user instead of performing an OAuth exchange.

Assistant and skills

Providers

ProviderNeedsDefault model
Apple IntelligenceNo key; simulated on-device serviceon-device
OpenAIAPI keygpt-4o
AnthropicAPI keyclaude-3-5-sonnet-20240620
OllamaBase URL, optional keyllama3
  • AIProviderConfig stores type, model and optional base URL in UserDefaults under igelnotes_aiprovider_config. The API key is deliberately excluded from Codable and lives in the Keychain, service com.igelnotes.aiprovider, account equal to the provider name.
  • The default provider is Apple Intelligence. In the current source it is a rule-based mock: generateBlocks recognises a few keywords, returns a canned list and otherwise echoes the prompt; generateText does the same. It opens no connection, but it is not a model integration yet.
  • Every provider implements AIAgentService: generateBlocks, fetchAvailableModels and generateText. The standard system prompt forces a JSON object with a blocks array so the reply can be inserted directly.
  • NoteActionExecutor parses assistant output for create_note, edit_note, delete_note and read_note, then applies it to SwiftData. Markdown tables are converted to TableData.

Kigel AI skills

Skills are SwiftData rows containing Markdown instructions. Four built-ins ship with the app: Note Writer, Task Planner, Brainstorm and Analyser. They cannot be deleted. Custom skills import from Markdown with a YAML frontmatter block (name, description) and export in the same format. Active skills are concatenated into the system prompt, so they change how the assistant structures notes without any server-side component.

Build and verify

# No Xcode project is committed. Create one, add the Appwrite Swift package,
# then build the iOS/iPadOS/macOS targets with Xcode 16+ and the iOS 18 SDK.

# Static verification, no Appwrite SDK required
./scripts/verify.sh

verify.sh runs four steps: parse every Swift file with xcrun swiftc -parse; reject residue from removed integrations (Hermes, the old agent registry and export payloads); reject secrets assigned as string literals; and compile a standalone logic harness from the models. The harness performs 166 checks on block types, note/block behaviour, templates, table data and skill parsing. It is not a full type-check of the app, because the Appwrite package is not vendored.

CloudKit is a target, not a feature. The README and the development plan both describe iCloud/CloudKit as the intended sync and Appwrite as temporary. The current tree does the opposite: local store plus Appwrite, with the iCloud entitlements commented out.

MCP status

Not implemented No binary App Intents only

There is no MCP server in the repository and no frozen tool schema. The development plan lists MCP as a perspective: expose the same intents as tools so an agent can search and append without extra credentials. Until that exists, the supported agent surface is the AI provider configuration plus the five App Intents above.
