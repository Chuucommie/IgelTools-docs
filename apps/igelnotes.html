IgelNotes

A block editor for the Apple stack: 21 block types, PencilKit drawing, SwiftData storage, optional Appwrite sync, 17 App Intents, a real Apple Intelligence provider and a 34-tool MCP server on Mac.

iPhone · iPad · Mac Catalyst SwiftUI · SwiftData · Appwrite MCP: local HTTP CloudKit not active

Overview

A note is an ordered list of typed blocks stored in SwiftData on the device. The app runs fully local. Synchronisation is optional and goes to an Appwrite instance the user configures; CloudKit is still not enabled. On Mac the app can start a loopback MCP server, off by default, that exposes notes, blocks, tables, tags, workspaces, skills and sync status to an agent. The transport can run on iPadOS too, but the current iPad UI does not expose the toggle; iPhone has no server.

The project targets iOS 18 for iPhone and iPad. Mac support comes from Mac Catalyst and Designed for iPad; a native macOS target is not in the Xcode project yet. The Xcode project is generated from project.yml with XcodeGen.

Functional documentation

What you can do

  • Write in blocks. Headings, text, todos, bullet and numbered lists, toggles, quotes, code, dividers, tables, drawings, images, sub-pages, page links, callouts, video, audio, files and web bookmarks: 21 types.
  • Tables. Columns, rows, header row, inline cell editing, add/remove column and row.
  • Draw. A PencilKit canvas as a block, with Apple Pencil and Scribble on iPad.
  • Organise. Workspaces, tags, favourites, emoji and cover, nested notes, links between pages, multi-select move and duplicate.
  • Find and recover. Search over titles and block content, tag/favourite filters, a trash with restore and a 30-day automatic purge.
  • Start from a template. Blank, shopping list, meeting notes, quick note and journal.
  • Dictate. On-device speech recognition through SFSpeechRecognizer (Italian locale).
  • Use Siri and Shortcuts. 17 App Intents, with 9 registered as Siri shortcuts.
  • Work with an assistant. OpenAI, Anthropic, Ollama or Apple Intelligence through Foundation Models, with keys in the Keychain.
  • Sync optionally. Pull and push blocks to Appwrite, with a URLSession WebSocket for realtime when the endpoint is a hostname.
  • Import. Notes from JSON, Markdown or plain text; Kigel skills import and export as Markdown with YAML frontmatter.
  • Drive it with an agent. The MCP server exposed in the Mac settings provides 34 tools, resources and prompts over loopback HTTP.

Limitations

  • No native macOS target: Mac support is Mac Catalyst and Designed for iPad. The Catalyst build needs the Appwrite and SwiftNIO packages resolved by Xcode.
  • CloudKit is not active: the iCloud entitlements are commented out and the store is local. The sharing sheet and CloudKit share code exist but cannot work without that capability.
  • The Google, Microsoft, Passkey and SSO buttons are placeholders. Apple sign-in is a local mock. Working paths are email/password with Appwrite, or Continue without an account.
  • Appwrite realtime requires a hostname; a direct IP endpoint is refused for the WebSocket subscription.
  • Apple Intelligence requires iOS 26 / macOS 26, an eligible device and Apple Intelligence enabled. It now throws an explicit error when unavailable instead of faking a response.
  • The MCP server is exposed in the Mac settings only, is off by default and listens on loopback. The transport can bind on iPadOS, but the iPad UI does not expose it yet; iPhone has no server and keeps the App Intents.
  • Siri shortcuts need the Siri capability; com.apple.developer.siri is present but commented in the entitlements.
  • The published DMG is ad-hoc signed; Developer ID signing and notarization are still needed for a warning-free distribution.

Sync, storage and authentication

Local store

IgelNotesApp builds a ModelContainer with Workspace, Agent, Note, NoteBlock, AIChat, AIChatMessage and KigelSkill, using the named configuration IgelNotes. There is no CloudKit container.

Appwrite (optional)

DataWhere
isEnabled, endpoint, projectId, databaseId, collectionIdUserDefaults, key appwriteConfig
API keyKeychain, service <bundle id>.appwrite, account apiKey
Provider configUserDefaults, key igelnotes_aiprovider_config
Provider keysKeychain, service com.igelnotes.aiprovider
MCP tokenKeychain, service com.igelnotes.mcp, account bearer-token
  • Configuration is empty by default; sync stays off until endpoint, project, database and collection are filled in.
  • Blocks are documents keyed by the block UUID. Upload updates first, then creates; deletes remove the document. The realtime client is implemented with URLSessionWebSocketTask because Appwrite 23 removed the SDK Realtime class.
  • The Xcode project depends on Appwrite 23.4, SwiftNIO and SwiftCollections pinned to 1.6.0; CloudKit remains inactive.
  • Authentication: email/password against Appwrite when configured, or a local workspace. Face ID can lock an existing session. Social buttons are placeholders and Apple sign-in is a mock.

The other providers are real HTTP clients. AIAgentService exposes generateBlocks, fetchAvailableModels and generateText; the system prompt forces a JSON block response, and NoteActionExecutor applies create/edit/delete/read actions to SwiftData.

Kigel AI skills

Four built-ins ship with the app: Note Writer, Task Planner, Brainstorm and Analyser. Custom skills import from Markdown with YAML frontmatter and export in the same shape. Active skills are concatenated into the system prompt; they are also exposed over MCP through skills_list and skills_get.

MCP server

Available in 1.0.0 Transport: loopback HTTP 34 tools Off by default

The server runs inside the app on Mac, not as a separate binary. It listens only on 127.0.0.1, uses POST /mcp, requires a bearer token and is disabled until Settings → Server MCP is enabled. The same runtime can bind on iPadOS, but the current iPad UI does not expose the toggle; iPhone has no server.

Setup

  1. Open Settings → Server MCP, turn the server on and choose the profile: read, write or destructive. Default is read.
  2. Pick a port (default 8765) and copy the generated client configuration. The token lives in the Keychain, service com.igelnotes.mcp; regenerating it invalidates existing clients.
  3. The endpoint is http://127.0.0.1:8765/mcp with Authorization: Bearer <token>.
{
  "mcpServers": {
    "igelnotes": {
      "type": "http",
      "url": "http://127.0.0.1:8765/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}

The HTTP transport accepts one request per connection (Connection: close), a JSON-RPC body up to 1 MiB, and returns JSON. The rate limiter allows 60 requests per minute; the in-memory audit keeps 1000 entries with tool, outcome and duration, never note content.

Resources and prompts

  • Resources: igelnotes://index/notes, /tags, /workspaces, /skills; templates for note/{id} (Markdown), note/{id}/json, block/{id}, table/{id}, skill/{name}, workspace/{id} and note/{id}/attachment/{block_id}.
  • Prompts: riassumi_nota, estrai_azioni, rivedi_nota, note_riunione, lista_spesa_da_testo.
  • Completions: note ids/titles, tags, workspaces, block types and export formats are suggested from the live store.

Build and verify

# Regenerate the Xcode project after changing project.yml
xcodegen generate

# Build without signing
xcodebuild -project IgelNotes.xcodeproj -scheme IgelNotes \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO build

# Mac Catalyst release used for the DMG
xcodebuild -project IgelNotes.xcodeproj -scheme IgelNotes \
  -destination 'platform=macOS,variant=Mac Catalyst' \
  -configuration Release CODE_SIGNING_ALLOWED=NO build

# Static checks, logic and MCP tests (no Appwrite account needed)
./scripts/verify.sh

verify.sh now has five steps: parse every Swift file; reject removed-integration residue; reject literal secrets; run 166 logic checks; and run 130 domain/MCP/HTTP checks, including a real loopback server on an ephemeral port. It is not a full Xcode type-check. Dependencies are resolved by Xcode: Appwrite 23.4, SwiftNIO and SwiftCollections 1.6.0.
