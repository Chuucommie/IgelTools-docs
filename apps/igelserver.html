IgelServer

A remote console for a headless Linux server over SSH: telemetry, systemd, Docker and qBittorrent, from a Mac or a Steam Deck.

macOS + Linux builds Rust · Tauri · SwiftUI MCP available No release yet

Overview

IgelServer keeps server profiles and connects over SSH to the host you already administer. There is no agent on the server and no IgelTools relay. The Linux build is Rust with Tauri; the macOS app is SwiftUI. Both talk to the same kind of server profile.

Functional documentation

What you can do

  • Profiles. Host, port, user, authentication method, SSH key path, timeouts and qBittorrent settings.
  • Telemetry. CPU, memory, swap, disk partitions, uptime, load and live network throughput, polled every few seconds.
  • systemd. List services, see failed units, start/stop/restart, and read journal lines without a terminal pager.
  • Docker. List containers (running and stopped), start/stop/restart, and stream logs.
  • qBittorrent. List torrents, add magnet links or torrent URLs, pause, resume and delete.
  • App Hub. A launchpad for the web interfaces on the server, opened in the default browser.

First run

  1. Open the app and edit the default profile in Configurazione: host, user and authentication.
  2. Use an SSH key where possible. The key stays on the local machine; the server sees only the public key.
  3. Unlock the vault to store passwords and sudo secrets.
  4. Connect. The profile's host key is verified on first use and pinned.

Limitations

  • The interactive terminal is a command runner with a timeout, not a full PTY yet.
  • qBittorrent control assumes its WebUI is reachable at the profile's host and port; a separate tunnel is the user's choice.
  • The macOS and Linux builds are packaged by the project pipeline; no public release exists yet.

Technical documentation

Architecture

  • Linux: Rust workspace, Tauri v2 shell, a library crate with modules for SSH, telemetry, systemd, Docker, qBittorrent, config, vault, updater and Tauri commands.
  • macOS: Swift 6 and SwiftUI, with its own profile and Keychain integration.
  • Connection: one multiplexed SSH session per profile (libssh2 on Linux), commands serialised to avoid interleaving on a blocking session.

Storage

ItemLocationNotes
Profiles~/.config/ServerPulse/config.jsonDirectory 0700, file 0600, atomic replacement.
Vault~/.config/ServerPulse/credentials_vault.encAES-256-GCM with Argon2id, bound to the machine; secrets are stripped from the config after unlock.
Known hostsPlatform SSH known-hosts storeTrust on first use, pinned afterwards; a mismatch aborts.

Security model

  • Passwords are never passed as process arguments. Sudo passwords go to sudo -S over the SSH channel's stdin.
  • Remote output is treated as untrusted; HTML is escaped. Unit and container identifiers are validated before entering a shell command.
  • The vault protects secrets at rest against other local users and casual disk inspection, not against code execution as the same user.
  • Prefer keys over passwords, and Tailscale/WireGuard over exposing SSH or the qBittorrent WebUI to the internet.

Build

cd ServerManager
cargo build -p serverpulse --release        # the Linux app
cargo test -p serverpulse
cargo build -p igelserver-mcp --release     # the MCP server, no Tauri needed

The MCP crate is a workspace member (mcp/) and depends only on serde, serde_json and ureq, so it builds without the GTK/WebKit dependencies required by Tauri.

MCP server

Available Binary: igelserver-mcp Config: app profiles

The server is a small companion binary. It reads the same profiles as the app and uses the system ssh client for connections; it does not need the Tauri runtime.

Build and register

cd ServerManager
cargo build -p igelserver-mcp --release
install -Dm755 target/release/igelserver-mcp ~/.local/bin/igelserver-mcp
{
  "mcpServers": {
    "igelserver": {
      "command": "/home/you/.local/bin/igelserver-mcp",
      "env": {
        "IGELSERVER_SUDO_PASSWORD": "…",
        "IGELSERVER_QBIT_PASSWORD": "…"
      }
    }
  }
}

Configuration resolution

ThingSource
ProfilesIGELSERVER_CONFIG, else ~/.config/ServerPulse/config.json.
Active profileactive_profile_id; every tool accepts an optional profile id.
SSH authenticationKey-based profiles: the profile's key_path (~ expanded) with ssh -i and BatchMode=yes.
SSH agentsThe system ssh client and the user's agent are honoured when no key path is required.
Sudo passwordIGELSERVER_SUDO_PASSWORD; otherwise sudo -n and the server reports the failure.
qBittorrent passwordProfile qbit_pass, else IGELSERVER_QBIT_PASSWORD.

Vault not opened by MCP. The encrypted vault is machine-bound and unlocked by the app. The MCP server cannot decrypt it, so password-only SSH profiles need an agent/key, and sudo/qBittorrent secrets come from the environment (or plaintext profile fields if they exist).

Validation and safety

  • Unit names accept only letters, digits, - _ . @ :; container names only letters, digits, - _ .; torrent hashes are hex, 8–64 characters.
  • There is no arbitrary-command tool. The MCP surface is the same set of operations as the app's commands.
  • Action tools are not read-only, so a host can gate them behind approval.
  • Sudo passwords are sent on stdin to sudo -S, never as an argument.
  • SSH uses BatchMode=yes: it never blocks waiting for a password prompt.
