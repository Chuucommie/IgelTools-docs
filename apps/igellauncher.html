IgelLauncher

A native SwiftUI macOS window that installs, updates and opens the IgelTools suite. An embedded catalog, SHA-256 verification, receipts and a 13-tool stdio MCP server in the same binary.

macOS 13+ Swift 5.9+ · SwiftUI · SwiftPM v0.1.0 MCP available

Overview

IgelLauncher is the suite manager, not one of the controlled apps. It reads a catalog embedded in the SwiftPM resource bundle, detects what is installed, checks the shared release repository, chooses the macOS build for the current CPU and installs it in ~/Applications after verifying the published SHA-256.

The app is native SwiftUI, built with SwiftPM and macOS 13 as the minimum. There is no Electron and no web view. The same executable also runs as a stdio MCP server when the first argument is mcp or --mcp.

Functional documentation

What you can do

  • Browse the suite. Three apps in a card grid or a table, with search over name, tagline and description, and a filter for installed apps.
  • See install state. Receipts come first; without one, the launcher checks /Applications and ~/Applications for the catalog's bundle names and marks the copy as external.
  • Install. Pick the macOS DMG, tar.gz, pkg or ZIP for the Mac's CPU, download it, verify the SHA-256 and install an .app from a DMG or tar.gz.
  • Update one or all. Compare versions against the release repository, update an app, or queue every app with an installable update; jobs show progress and can be cancelled.
  • Open and remove. Open an installed app from the window; uninstall only the copies the launcher installed itself.
  • Check the launcher. The launcher checks its own release too and downloads the update file without replacing the running bundle.
  • Work in three languages. English, Italian and German; Automatic follows the system locale.
  • Read the log. The window shows the current log and can copy it; the file rotates on launch.
  • Use an agent. IgelLauncher mcp exposes the catalog, installs, updates, settings and logs over stdio with 13 tools.

Pages

  • Library: the suite, search, All/Installed filter and the grid/table switch.
  • Updates: per-app rows, Update all and the launcher's own update row.
  • Settings: language, check on start, pre-releases, checksum policy, GitHub token, install folder, repository overrides and shortcuts to the data folder and log file.
  • Logs: the rotating log tail with a copy button.

First run

  1. Run swift run IgelLauncher or the installed IgelLauncher.app. It creates its folders and loads default settings; settings.json is written when you save the Settings page.
  2. The default release repository is public. A GitHub token is optional, useful for forks and higher API limits; it is stored as plain text in settings.json.
  3. Optionally override the repository for one app, or point IGEL_LAUNCHER_MANIFEST at a local feed.
  4. Press Check for updates (check_on_start is on by default). Install an app; the launcher downloads, verifies and records a receipt.

Build

swift build
swift run IgelLauncher
./install.sh     # ~/Applications/IgelLauncher.app

# MCP mode
swift run IgelLauncher mcp

Requirements are macOS 13 or later and Xcode 15 or later (Swift 5.9+). install.sh builds the release binary, writes the Info.plist, copies the SwiftPM resource bundle, generates the .icns with sips/iconutil and installs the app in ~/Applications. The bundle identifier is io.igeltools.launcher; the executable is IgelLauncher; the plist declares LSMinimumSystemVersion 13.0.

The window opens at 1120×740 and can shrink to its minimum content size. There is no automated test target in the repository yet.

Catalog

Sources/IgelLauncher/Resources/suite.json is copied into the SwiftPM resource bundle. It contains Igel TVRemote, IgelNotes, IgelServer and the launcher entry, with icons and accent colours. For each app the launcher reads:

FieldUse
id, name, tagline, descriptionDisplay, search and MCP output.
repo, release_prefixRelease repository and tag namespace. The default is the shared Chuucommie/IgelTools-Releases.
targetsAvailability on macOS; every shipped app currently targets macOS.
mac_bundlesBundle names for external detection and for finding the .app inside a DMG or tar.gz.
icon, accent, webEmbedded icon, UI accent and the website link.

Because all apps publish in one repository, the launcher filters releases by release_prefix: igeltvremote, igelnotes, igelserver and igellauncher.

Release lookup and versioning

  • GitHub mode calls GET https://api.github.com/repos/<owner>/<repo>/releases?per_page=100 with the GitHub JSON media type, API version 2022-11-28 and user agent IgelLauncher.
  • A 404 means no release and is reported as No release published yet. Other HTTP errors are shown with the status and a short body.
  • Releases are filtered by tag prefix, drafts are ignored, and a prerelease is chosen only when allow_prereleases is on.
  • IGEL_LAUNCHER_MANIFEST bypasses GitHub and reads a local JSON feed; IGEL_LAUNCHER_DOWNLOAD_BASE rewrites manifest asset URLs to a mirror.
  • Version comparison strips a leading v, compares numeric components and sorts a prerelease below its release.

Asset selection

Only macOS assets are considered. DMG and pkg are accepted by extension; tar.gz and ZIP must mention macOS (macos, mac, darwin or universal). Assets for the other CPU are skipped unless universal.

PreferenceKindLauncher installs it?
1.dmgYes: mount, copy the .app, detach.
2.tar.gz / .tgzYes: extract, copy the .app.
3.pkgNo: download only, install with the macOS installer.
4.zipNo: download only, open in Finder.

Architecture tokens match x86_64, x64, amd64, aarch64, arm64 and arm-64; universal matches both.

Install pipeline

  1. Pick the latest release for the app and select the best macOS asset for the current CPU.
  2. Resolve the expected SHA-256 from the asset sha256, the GitHub digest, or a release file named SHA256SUMS.txt, sha256sums.txt, checksums.txt or *.sha256.
  3. If no checksum exists and require_checksum is on, refuse the install. The default is on.
  4. Download to the data folder's tmp/; a cancellation removes the partial file.
  5. Compute SHA-256. A mismatch deletes the file and aborts.
  6. DMG: hdiutil mounts the image read-only, the expected .app is copied with cp -R, then the image is detached.
  7. tar.gz: /usr/bin/tar extracts into a scratch folder; the expected .app is copied to the install folder.
  8. Replace an existing bundle, write the receipt to installed.json, delete the temporary download and log the result.

The install folder is ~/Applications unless install_dir overrides it. pkg and ZIP are never installed by the launcher.

Receipts and updates

installed.json maps an app id to version, path, kind (dmg or targz), managed and installed_at. A copy found in /Applications or ~/Applications without a receipt is external, managed: false, with no version.

  • A receipted app with an installable asset newer than its version offers Update; with only a newer pkg/ZIP it offers Download; otherwise Open.
  • An app with no receipt offers Install for DMG/tar.gz, or Download for pkg/ZIP.
  • External copies are never updated or uninstalled. The MCP uninstall tool refuses them.
  • Update all queues every app with an available update; the queue skips assets the launcher cannot install.

Self-update

The launcher checks the same shared repository with the igellauncher prefix. Download update writes the selected asset to …/updates/ and verifies the SHA-256 when one is published. It does not enforce require_checksum for this download and does not replace the running bundle; the window shows the path. In-place replacement is not implemented.

MCP server

Available in source Binary: IgelLauncher Args: mcp 13 tools

The app and the server are one executable. In MCP mode it opens no window: it reads newline-delimited JSON-RPC 2.0 from stdin, writes responses to stdout and appends operational logs to the rotating log file. It advertises protocol 2025-06-18 and tools with listChanged: false.

IgelLauncher mcp
# or
IgelLauncher --mcp

Register it

{
  "mcpServers": {
    "igellauncher": {
      "command": "/Users/you/Applications/IgelLauncher.app/Contents/MacOS/IgelLauncher",
      "args": ["mcp"]
    }
  }
}

When built in place the binary is .build/release/IgelLauncher; after install.sh it lives inside the app bundle.

A successful call returns one text content block with pretty-printed JSON. Tool failures set isError: true. The launcher annotations are correct: install/update/download are not read-only, and uninstall declares destructiveHint.

Limits and security notes

  • macOS only. No Linux or Windows build, and no cross-platform runtime.
  • No signature verification. Integrity means SHA-256; the launcher does not check Developer ID or notarization before copying a bundle.
  • Token on disk. github_token is plain text in settings.json.
  • Self-update is download-only and does not enforce require_checksum; it verifies only when a checksum is published.
  • External installs stay external: they are listed and can be opened, but not updated or uninstalled.
  • Catalog descriptions are display strings. The current suite.json still contains older copy for IgelNotes and IgelServer; the app pages are authoritative.
  • No tray icon and no signed/notarized launcher DMG yet. install.sh builds a local bundle.
