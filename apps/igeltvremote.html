Igel TVRemote

A network remote for the smart TVs already on your Wi-Fi, for iPhone, Apple Watch and Mac. Discovery, one pairing per TV, then keys, text and wake-on-LAN over the local network.

macOS · iOS · watchOS Swift 6 · SwiftUI No MCP server No release yet

Overview

The app discovers TVs on the current network, pairs once, stores the credential in the Keychain and sends commands directly to the TV. There is no account, no cloud relay and no analytics. Commands travel over the network; there is no infrared emitter and therefore no line-of-sight requirement.

One Swift package holds the protocol adapters, discovery and persistence. The macOS app is a small SwiftUI window; the iOS and watchOS apps are generated from an XcodeGen project. The watch relays commands to its paired iPhone over WatchConnectivity, and the watch never talks to the TV directly.

Functional documentation

What you can do

  • Find TVs on the current network, or add one by IP address.
  • Pair once per TV and reconnect automatically, including after a DHCP address change.
  • Send the shared command set: d-pad, OK, back, home, menu, exit, source, info, guide, tools, volume, mute, channel, playback, number pad and colour keys where the platform supports them.
  • Enter text on the TV from the iPhone keyboard for protocols with a text channel.
  • Control the Mac with hardware keyboard shortcuts mapped to remote commands.
  • Wake a TV with Wake-on-LAN when its network interface stays alive in standby and its MAC address is known.
  • On Apple Watch, navigate by tapping or tilting the wrist, change volume with the Digital Crown, and use the keypad and media screens through the paired iPhone.
  • Ask Siri or Shortcuts to power a Samsung TV on or off, mute it, or change the volume.

Requirements and permissions

  • macOS 13 or later, iOS 17 or later, watchOS 10 or later; Swift 6 and Xcode 27.
  • Local Network permission on first launch. Without it, discovery returns no results because the platform blocks the socket before a packet leaves the device.
  • iPhone, Mac and watch must be on the same network as the TV. A watch controls through its paired iPhone.

Architecture

  • IgelTVRemoteCore declares macOS 13, iOS 17 and watchOS 10. Its only external dependency is attaswift/BigInt, used by the JPAKE exchange for Fire TV.
  • Every non-Samsung platform implements TVRemoteAdapter: connect, disconnect, send(_ command: TVCommand), sendText and currentCredential.
  • TVRemoteAdapterFactory maps a TVProtocolID to an adapter. Samsung is the exception: the factory returns nil, because Samsung keeps its own WebSocket client and key vocabulary.
  • TVRemoteSession is the protocol-agnostic facade used by the iOS and macOS clients for every non-Samsung TV. It guards the adapter and credential state with a lock and owns the adapter lifetime.
  • The UI only sees TVCommand and TVCapabilities; it never learns which protocol is behind a TV. The UI hides unsupported keys instead of sending commands that would fail.

Discovery

Discovery runs several sources in parallel and merges the results by stable identity:

  • SSDP on 239.255.255.250:1900, sent from every broadcast-capable IPv4 interface. Samsung uses urn:samsung.com:device:RemoteControlReceiver:1 with MediaRenderer as a fallback target.
  • Bonjour records for _amzn-wplay._tcp (Fire TV) and _androidtvremote2._tcp (Android TV).
  • Subnet sweep over the active local subnet, probing candidate ports with non-blocking sockets so a dead host does not stall the sweep. This finds TVs on networks that filter multicast.

MultiBrandProbe only accepts private IPv4 addresses. It probes 6466, 43445, 8001, 8060, 3000 and 1925 first; the thorough pass adds 42989, 55000 and 9000, plus port 80 for Sony when enabled. An open port is not treated as proof of a platform: LG on 3000 is accepted only after a real 101 Switching Protocols, and Roku and Philips must return a valid device description before they are claimed.

A saved TV keeps its stable id, display name, model, OS, DUID, Wi-Fi and wired MACs, last known IP and port, pairing identity, network ids and per-TV settings (auto-connect, Wake-on-LAN and MAC preference, transport preference, legacy WebSocket, favourite keys). A DHCP change updates the address, not the identity. Legacy builds stored tokens by IP; the token store has a migration path that adopts such a token when the discovered TV validates the address.

Wake-on-LAN

The magic packet is sent to the subnet broadcast address derived from the TV's IP and netmask, using either MAC. The app only offers the button when a MAC is known. Fire TV exposes no MAC, so it is woken through ADB instead: adbd stays reachable in standby and the power key brings it back. On iOS the app does not offer Wake-on-LAN at all, because it would need the multicast/broadcast entitlement.

Apple Watch

  • A WatchConnectivityManager sends send_key and send_text messages to the iPhone, which owns the TV session. Application context carries the active TV identity and token so the watch can label the remote.
  • The Digital Crown drives volume through a speed-adaptive leaky bucket, avoiding one key event per crown tick.
  • A CoreMotion classifier runs at about 33 Hz, recognises wrist tilt for navigation and a fist-clench trigger, and emits haptics when the gesture clutch engages or releases.
  • The watch UI includes a d-pad, keypad/channel screen and a media/system screen.

App Intents

The iOS target ships five Samsung-specific intents: power off, power on (Wake-on-LAN plus a power key), mute, volume up and volume down. They run without opening the app and read the active TV from AppRepository. If no TV is saved, they return a dialog asking the user to add one.

Build and test

# macOS app bundle (ad-hoc signed)
./scripts/package_mac_app.sh
open "dist/Igel TV Remote.app"

# Core and macOS test suites
(cd IgelTVRemoteCore && swift test)   # 22 tests
(cd IgelTVRemoteMac && swift test)    # 23 tests

# Everything, including the shell suites and autosign checks
./tests/run_all_tests.sh

# Regenerate the iOS/watchOS project after editing project.yml
cd IgelTVRemoteiOS
xcodegen generate

Hardware and live-network suites are opt-in: LIVE_SCAN=1 for discovery, LIVE_ADB=1 with LIVE_ADB_HOST for Fire TV ADB, LIVE_FIRETV=1 for the WhisperLink handshake, TLS_TEST_HOST for mutual TLS and RUN_SLOW_CRYPTO=1 for the full JPAKE exchange. Two snapshot tests are skipped without a desktop session. CI runs both Swift suites on pushes and pull requests, and compiles the iOS and watchOS targets unsigned.

For distribution, replace the ad-hoc signature with a Developer ID identity and notarize the result; the iOS and watchOS targets need your development team under Signing & Capabilities. A local LaunchAgent can re-sign and reinstall the iOS app every 12 hours, because free provisioning expires after 7 days.

Limitations

  • Apple TV is not supported. There is no infrared, so IR-only TVs cannot be controlled.
  • Fire TV is marked Limited: without developer options and ADB debugging, a current Fire OS device cannot be controlled at all.
  • On iPhone, raw SSDP needs the com.apple.developer.networking.multicast entitlement. Until it is granted, discovery relies on Bonjour and the subnet scan, and Wake-on-LAN is not offered.
  • Roku OS 14.1 requires Settings → System → Advanced system settings → Control by mobile apps to be enabled, or key presses return 401.
  • A pairing token is tied to the client identity. A build with a different bundle identifier counts as a new client and must pair again.
  • Nothing has been released yet. The App Store metadata is being prepared in appStore/.

MCP status

Not implemented No binary Local-only app

There is no MCP server in the repository. Earlier documentation described a frozen igeltvremote-mcp contract, but no such binary or module exists in the current tree. If one is added, it would run on the Mac that owns the saved TVs and Keychain items, reuse AppRepository and TVTokenStore, and leave pairing in the app because a human must accept the prompt or enter the PIN. The App Intents remain the only supported automation surface today.
