Igel TVRemote

A network remote for the smart TVs already on your Wi-Fi, for iPhone, Apple Watch and Mac. Discovery, one pairing per TV, then keys, text and wake-on-LAN.

macOS · iOS · watchOS Swift 6 · SwiftUI MCP contract v1 No release yet

Overview

The app discovers TVs over the local network, pairs once, keeps the credential in the Keychain and sends commands directly to the TV. There is no account, no cloud relay and no analytics. Commands go over the network, not infrared.

Functional documentation

What you can do

  • Find TVs on the current network, or enter an IP address manually.
  • Pair once per TV and reconnect automatically afterwards, including after a DHCP address change.
  • Send the full key set: d-pad, OK, back, home, menu, volume, mute, channel, playback, number pad and colour keys where the TV supports them.
  • Type text from the phone or computer keyboard instead of using an on-screen grid.
  • Wake a TV with Wake-on-LAN when its network interface stays alive in standby.
  • On Apple Watch, control through the paired iPhone: tap or tilt to navigate, Digital Crown for volume, plus a keypad and media screen.

Requirements and permissions

  • macOS 13 or later, iOS 17 or later, watchOS 10 or later.
  • Local Network permission on first launch. Without it, discovery returns no results because the platform blocks the socket before a packet is sent.
  • iPhone, Mac and watch must be on the same network as the TV. A watch controls through its paired iPhone.

Technical documentation

Package layout

  • SamsungRemoteCore is the shared Swift package: discovery, one adapter per protocol, persistence and keychain access.
  • SamsungRemoteMac is the macOS app target; the iOS and watchOS targets are generated from SamsungRemoteiOS/project.yml with XcodeGen.
  • TVRemoteAdapterFactory maps a TVProtocolID to an adapter; TVRemoteSession is the protocol-agnostic facade used by both apps.

Discovery

Three sources run in parallel: SSDP on 239.255.255.250:1900, Bonjour records (_amzn-wplay._tcp for Fire TV, _androidtvremote2._tcp for Android TV), and a scan of the local subnet that probes the candidate ports. A probe returns the device description plus the protocol that can actually control it, which can be more specific than the brand.

MCP contract

Contract v1 macOS server next Binary: igeltvremote-mcp

Status. The tool contract below is frozen for the first server release. The implementation is a macOS 13+ executable built from SamsungRemoteCore; it is the next milestone for this app. It is documented here so clients and agents can be built against a stable surface.

Design

  • Runs on the Mac that already has the app's saved TVs and Keychain credentials. It reads the same AppRepository file and TVTokenStore.
  • Only controls TVs that were paired in the app. Pairing needs a human at the TV (prompt or PIN), so it stays in the app; an unpaired TV returns a clear error.
  • Commands are serialised per TV. Long discovery calls have a timeout.
  • The server exposes no network listener; transport is stdio.

Security rules

  • Credentials stay in the Keychain; tool results never include tokens or client keys.
  • LAN operations only. No cloud discovery and no remote relay.
  • send_key, send_text and wake_tv are not read-only.
  • Pairing and unpairing stay in the app, where the user can see the TV prompt.
